# 01 · Restructure (X3)

Branch `seshi-01-restructure`, on `seshi`. Today's code moved into the X3 layout with no change in what the server stores or answers. All 327 existing tests pass, moved next to their code or into `tests/`; the goldens regenerate byte for byte (`bun run goldens`, `bun run fixtures` leave the tree clean).

## What was built

- **Layout.** `apps/seshi`, `packages/ts/{model,kit,formats,redact,config,store,pipeline,auth,sources,search,instance,api,capture,client}`, `integrations/{claude-code,codex,cursor,datadog-trajectory,opencode,pi,gemini-cli}`, `tests/`. `sdks/typescript` and `server/` are gone. Every package is `"private": true`, named `@seshi/<name>` (integrations `@seshi/integration-<name>`, the app `seshi`), depends on others as `workspace:*`, and exports `./src/index.ts` through the `bun` condition only. `config`, `sources`, `search`, `instance` and `capture` hold an empty `src/index.ts`.
- **Where the code went.** As in the decisions' table. `schemas/*`, `trace/canonical.ts`, `trace/parse.ts`, `ingest/prefix-hash.ts` (now with `canonicalJson` and `prefixSha256`), `ingest/errors.ts` → `ts/model`. `normalize/{atif,trajectory,detect}.ts`, `normalize/index.ts` (now `registry.ts`), `trace/otlp.ts` → `ts/formats`. `redact/*` → `ts/redact`, `store/*` → `ts/store`, `ingest/*` → `ts/pipeline`. `client.ts` split: `HttpSeshi` → `ts/client`, `StoreSeshi`/`connect` → `ts/pipeline/src/local.ts`. `server/src/app.ts` → `ts/api`, `signed-token.ts` → `ts/auth`, `main.ts` → `apps/seshi/src/commands/serve.ts`. Vendor transcripts and their goldens → `integrations/<vendor>/testdata/{transcripts,goldens}`; ATIF's → `packages/ts/formats/testdata/`; the `records/`, `edge-*` and `reject-*` goldens stay in `spec/testdata`. `trace/goldens.ts`, `scripts/{fixtures,goldens}.ts` → `tests/tooling/`.
- **Types every layer shares live in `ts/model`:** the session API (`Seshi`, `Upload`, `SessionUpload`, `StoreSessionResult`, `StoredTrace`, `ChangesPage`, `StorageView`, `Fetch`, …), the errors (`SessionRejected`, `IngestRejected`, `OffsetMismatch`, and `StoreError`, so `ts/client` throws the same class without depending on `ts/store`), and `VERSION`, read from `packages/ts/model/package.json`, the repository's one version.
- **Integration contract (X3.11).** `ts/kit` exports `Integration` (`name`, `formats`, `hooks`, `sweepPaths`, `connectors`, `installers`), declares `HookHandler`, `Connector`, `Installer` as placeholder types, and has `defineIntegration` (validates the name and format list) and `formatsOf(integrations)` (refuses a duplicate integration or format). Each integration's `src/index.ts` exports one `defineIntegration(...)` object.
- **Format registry.** `ts/formats` `FormatRegistry` replaces `SOURCES`/`isSource`/`isChunkable`/`detectSource`/`normalizeTranscript`: `sources`, `has`, `get`, `isChunkable`, `detect(sample)` (asks each adapter's `detect.document`/`detect.record`), `normalize(input, { postprocess })`. `lettaAdapter({ source, detect, prepare, finish, chunkable })` builds an adapter over `@letta-ai/trajectory`; `ATIF_FORMAT` and `TRAJECTORY_FORMAT` are built in (`BUILTIN_FORMATS`).
- **Redaction moved out of normalization.** `ts/formats` may not import `ts/redact` (same layer), so `ts/pipeline` `normalizeTranscript(formats, input)` runs the registry with `redactRecords` as `postprocess`. The outcome is decided after redaction as before.
- **Threading the registry.** `storeSession` options, `StoreSeshi`, `connect({ store, … })` and `createApp` take a required `formats: FormatRegistry`. `agent` is now a plain string, so `storeSession` refuses one the registry does not know (`SessionRejected("unsupported_agent")`, the API's wording) before it writes anything; the closed `Source` type used to guarantee that at compile time. `apps/seshi/src/integrations.ts` holds `INTEGRATIONS` (static) and `buildFormats(integrations = INTEGRATIONS)`.
- **The binary.** `apps/seshi/src/main.ts` (the package's `bin`, so it starts with `#!/usr/bin/env bun` and is executable) exports `main(argv, options)`; `seshi --version` (`-v`, `version`) prints `seshi <VERSION>`, `--help` lists commands, no command or an unknown one exits 2. `src/commands/index.ts` is the command registry: `{ summary, load: () => import("./x") }`, so a command's module is imported only when it runs. `seshi serve` runs today's server from the pre-seshi environment variables (`readServeEnv` is the pure, tested part). `bun start`, `bun run seshi -- <cmd>`.
- **Layer check.** `scripts/check-layers.ts`, run by `bun run check` after Biome. It reads every import (TypeScript's `preProcessFile`: type-only, re-exports, `import()` included) in `apps/`, `packages/ts/`, `integrations/`, `tests/`, `scripts/` and enforces: lower layers only (layers exactly as X3.2, with `ts/client` on layer 1); integrations → only model, kit, formats; `ts/client` → only model; `ts/capture` → only model, kit, redact, config, client; only apps import integrations; nothing imports `tests/` or `scripts/`; no relative import across packages; every workspace import declared in the importer's `package.json` (root `package.json` for `tests/` and `scripts/`). A new folder in `packages/ts` fails until it has a layer in `PACKAGE_LAYERS`.
- **Config and CI.** Root workspaces `apps/*`, `packages/ts/*`, `integrations/*`; tsconfig, Biome and Vitest globs cover them plus `tests/` and `scripts/`; Vitest resolves the `bun` condition through `resolve.conditions` (no alias). `apps/seshi/Dockerfile` copies the workspaces and runs `bun run apps/seshi/src/main.ts serve` (built and booted locally: `/healthz` answers). CI's live-S3 step runs `tests/store/s3-live.test.ts`; the docker and image jobs use the new Dockerfile.

## Extension points for later branches

- **New command:** add one entry to `COMMANDS` in `apps/seshi/src/commands/index.ts`; the module exports `run(ctx: CommandContext): Promise<number | undefined>` (`undefined` keeps the process running). `ctx.integrations()` gives the static registry. Never import a command module at the top of `main.ts` or the registry.
- **New integration:** `integrations/<name>/` with `package.json` (`@seshi/integration-<name>`, deps on `@seshi/kit` and what else it uses of model/formats), `src/index.ts` exporting `defineIntegration({...})`, fixtures in `testdata/`; add it to `INTEGRATIONS` in `apps/seshi/src/integrations.ts` and to `apps/seshi/package.json`. Its transcripts are picked up by `tests/goldens.test.ts` and `bun run goldens` automatically; add the source to `HOME` in `tests/tooling/fixtures.ts` if fixtures are generated.
- **New package:** add it to `PACKAGE_LAYERS` in `scripts/check-layers.ts`, and to the root `devDependencies` if `tests/` imports it (Bun uses the isolated linker: an undeclared workspace import does not resolve).
- **Filling `Integration`:** `HookHandler`, `Connector`, `Installer` in `ts/kit` are placeholders; 06 (connector context), 14 (hooks, sweep, installers) should replace them rather than add parallel types. `FormatAdapter` itself is defined in `ts/model/src/format-adapter.ts` and re-exported by kit.
- **Format registry consumers:** build one with `buildFormats()` in the app and pass it down. In package-local tests use `new FormatRegistry([...])` with fakes or `BUILTIN_FORMATS`; tests that need vendor adapters go in `tests/` and call `buildFormats()` from `seshi/integrations`.
- **Fixtures in tests:** `tests/tooling/testdata.ts` `transcript(file)`, `golden(file)`, `fixturePath(kind, file)` find a fixture in whichever `testdata/` holds it.
- **Version:** `VERSION` from `@seshi/model`; `scripts/release-version.ts` writes `packages/ts/model/package.json` and its `bun.lock` entry.

## Deviations and why

- **Branch names use a hyphen** (`seshi-01-restructure`). Git cannot create `refs/heads/seshi/…` while `refs/heads/seshi` exists. The build README table now uses hyphens.
- **`FormatAdapter` and its helper types live in `ts/model`**, re-exported by `ts/kit`. Kit and formats are both layer 1 and may not import each other, but formats must name the type to run detection and build adapters.
- **The session errors live in `ts/model`**, not `ts/pipeline` as the table says for `ingest/*`: `ts/client` throws `SessionRejected`, `OffsetMismatch` and `StoreError` from server answers and may depend only on `ts/model`. `ts/pipeline` re-exports them. Likewise the session API types (`Seshi`, `Upload`, …), `ShippedPrefix`, `canonicalJson` and `prefixSha256`.
- **`ts/client` is layer 1.** X3.2 says only that it depends on `ts/model`; placing it on layer 1 lets `ts/pipeline` hold `connect()` (which picks between the HTTP client and the store) until local mode replaces it in 06 (X3.5).
- **Integrations: one package per vendor folder**, sub-areas as folders under `src/` (`integrations/datadog-trajectory/src/daemon/`, `integrations/cursor/src/local/`), so each vendor exports one object. Four small integrations not named in the task (`cursor`, `opencode`, `pi`, `gemini-cli`) hold the detection rule and adapter for formats `@letta-ai/trajectory` reads as-is; that code is vendor-specific, so formats may not hold it.
- **`normalizeTranscript` moved to `ts/pipeline`** and takes the registry first; `ts/formats`' `FormatRegistry.normalize` returns unredacted records unless given a `postprocess`.
- **Format list order** in the `unsupported_agent` message is now the integrations' then the built-ins': `claude-code, cursor, codex, opencode, pi, gemini-cli, datadog-trajectory, atif, trajectory` (`atif` and `datadog-trajectory` swapped). Same set; no test or client depends on the order.
- **npm publishing is off.** No package is publishable any more (X3.4), so `release.config.js` only versions, tags and lets CI build the image; 15 adds the npm publish of `seshi` and `@seshi/client`. The traces still record `normalizer.name: "@dosu/seshi"`, the OTLP scope name and the default user agent are unchanged, so readers see no difference.
- **Tests that cross packages moved to `tests/`** (X3.6): the server suites (`tests/api/`), the direct-to-bucket client (`tests/pipeline/local.test.ts`), store redaction (`tests/pipeline/session-redaction.test.ts`), normalize/detect/trajectory/datadog through the real registry (`tests/formats/`), the OTLP store tests (`tests/formats/otlp-store.test.ts`), the live S3 test (`tests/store/s3-live.test.ts`), the ingest suite (`tests/pipeline/ingest.test.ts`, whose record sets include Claude Code's goldens) and the goldens check (`tests/goldens.test.ts`, which now walks every `testdata/goldens`). No package's own tests read another folder's `testdata/`.
- **`serve` keeps the pre-seshi env names, error prefix and marker client**, as the task says (02 replaces the env parsing).
